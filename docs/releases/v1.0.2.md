## Highlights

- Configure the shared SMTP sender in **Email settings**. Settings are encrypted in PostgreSQL and take effect for both the web app and worker without a restart.
- Startup helpers for macOS, Linux and Windows now compare the current build inputs with a fingerprint stored in the Docker image. Changed sources or branch contents trigger a rebuild; matching images are reused.
- Simplified the application around live, production ANAF connections, with HTTPS enabled by default and persistent application secrets generated automatically.
- Changed the project license to **BSD 3-Clause**.
- Reworked the README around installation and everyday use, added an example screenshot and a project roadmap, and separated development, architecture and operations guides.

## Fixes

- Restore complete legacy SMTP settings from `.env` into encrypted storage when no sender has been saved in the app. The migration preserves entity notification recipients and switches, works during concurrent web/worker startup, and never overwrites newer in-app settings.
- Require configured SMTP before enabling **Send E-invoice notification emails**. Entity settings show the server, sender and encryption settings; the dashboard distinguishes missing SMTP configuration from disabled entity notifications.
- Allow the application to start with an empty workspace or an ANAF connection that has no linked entity yet.
- Improve startup diagnostics and ensure source changes are reflected in the running web image.

## Maintenance

- Updated NestJS, Nodemailer, Vite and Docker build workflow dependencies.
- Added Dependabot auto-merge support and expanded coverage for HTTPS startup, SMTP persistence, secret migration and browser interactions.

## Upgrade notes

1. Back up PostgreSQL and your existing private configuration before upgrading. Retain any existing `APP_SESSION_SECRET` and `ANAF_TOKEN_ENCRYPTION_KEY` values during the first startup: they are imported into persistent application-secret files so existing sessions and encrypted authorizations remain readable. Keep the new `app-secrets` Docker volume alongside the database volume for subsequent restarts and backups.
2. Download this release's `compose.yaml`, `compose.release.yaml` and `env.release.example`. Replace the two Compose files together and compare the new environment template with your existing `.env`; preserve your private values rather than replacing the file wholesale. Set `EFACTURA_VERSION=1.0.2` and keep the database's existing `POSTGRES_PASSWORD`.
3. The Docker stack now requires HTTPS. Create and trust `.local/tls/localhost.pem` and `.local/tls/localhost-key.pem` using the [local HTTPS guide](../local-https.md). For the default installation, set `APP_PUBLIC_URL=https://localhost:8765` and `APP_TLS_PORT=8765`; the registered ANAF callback must match the exact HTTPS origin and port. The old `compose.https.yaml` override has been removed: HTTPS is included in the shared Compose configuration.
4. The normal stack no longer includes the local ANAF simulator or Mailpit. Only live, production ANAF connections are supported. Review legacy mock/test settings if running the app directly from source.
5. Check **Email settings** after the upgrade. Complete, explicitly configured legacy SMTP settings are imported automatically only when no sender is already stored. Otherwise configure the sender in the app, then review each entity's **Send E-invoice notification emails** switch. An implicit local mail server is no longer used.

After updating the files and configuration, apply the release:

```sh
docker compose --env-file .env -f compose.release.yaml pull
docker compose --env-file .env -f compose.release.yaml up -d --wait
```

Named volumes preserve existing accounts, entities, invoices and documents. Do not use `docker compose down -v`; it permanently deletes the database and application-secrets volumes. See the [operations guide](../operations.md) for older document migrations, recovery and troubleshooting.
